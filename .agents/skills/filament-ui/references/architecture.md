# Architecture

How Filament's `ui/` is put together, and the house conventions every new file follows. The DLS references in this folder say what the components are. This page says where code goes and how it is shaped.

## Stack

| Concern | Choice | Where |
|---|---|---|
| Build | Vite 8, `@wyw-in-js/vite` for Linaria, `@tanstack/router-plugin` with `autoCodeSplitting` | `ui/vite.config.ts` |
| UI | React 18, `@galaxy-io/dls` 2.x, Phosphor icons | everywhere under `ui/src` |
| Routing | TanStack Router, file based | `ui/src/routes/`, `ui/src/router.tsx` |
| Data | ConnectRPC over `@connectrpc/connect-query` + TanStack Query v5 | `ui/src/api/` |
| Types | protobuf-es generated from `api/**/*.proto` | `ui/src/gen/` (checked in, regenerate with `pnpm codegen`) |
| Styling | Linaria `styled` reading DLS tokens through `t` | per component file |
| Lint and format | Biome extending `@galaxy-io/dls/biome` | `ui/biome.json` |
| URL state | zod `validateSearch` schemas | each route file |
| Branching on enums | `ts-pattern` `match().exhaustive()` | where a component picks a branch per enum member |
| Canvas | `@xyflow/react` | `pages/pipelines/canvas/` |

There is no test runner. The gates are `pnpm typecheck`, `pnpm lint:check`, `pnpm format:check` and `pnpm build`, run from `ui/`.

## File contract

- **One primary export per file, default exported, filename equals the export.** Enums, props interfaces and small types that belong to that component are named exports from the same file.
- **Feature prefix on every name.** Everything under `pages/pipelines` is `Pipeline*` or `Pipelines*`. Canvas pieces are `PipelineCanvas*`. A component in `pages/connectors/components/drawer/` is `ConnectionDrawer*`. The prefix is the folder path, so a name tells you where the file is.
- **Next to its only consumer.** A component used by one screen lives in that screen's folder. It moves up to `components/` only when a second feature needs it.
- **Per-folder `constants.ts`, `types.ts`, `utils.ts`.** Each surface folder may have all three. App-generic helpers go to `src/utils/`.
- **No `index.ts` barrels.** Import the file. The Biome preset flags barrels.
- **No comments** except Biome directives and one-line notes about a constraint the code cannot show (a server behaviour the client mirrors, a library quirk). No section banners.
- **Soft budget of about 120 lines per component.** Split by responsibility when a file grows past it. A private render helper under about 30 lines may stay inline, unexported.
- **Hooks live in a `hooks/` folder inside the consuming feature.** Context accessor hooks are the exception and live in the Provider file. A hook with one consumer gets inlined.

## Naming

| Thing | Shape | Example |
|---|---|---|
| Constant | `SCREAMING_SNAKE`, feature prefixed | `PIPELINES_TABLE_COLUMN_WIDTH_STATUS`, `MAIN_LAYOUT_GUTTER` |
| Lookup | `X_TO_Y_MAP`, an exhaustive `Record` | `PIPELINE_RUN_STATUS_TO_HUE_MAP: Record<RunStatus, Hue \| null>` |
| Enum | `PascalCase` with `SCREAMING` members whose value equals the name | `enum Flow { CREATE_PIPELINE = "CREATE_PIPELINE" }` |
| Helper | verb first: `createX`, `mapXToY`, `getX`, `formatX`, `isX`, `hasX` | `createListPipelinesInput`, `mapPipelineVersionToCanvasState`, `formatPipelineName`, `isPipelineRunnable` |
| Boolean | `isX`, `hasX`, `canX`, `shouldX`, positive | `isLoading`, `hasChanges`, `canSave` |
| Handler | `handleX` inside the component, `onX` as a prop | `handleSave`, `onSortingChange` |
| Props | `<Component>Props` interface above the component | `interface PipelinesTableProps` |
| Page state | `<Component>State` interface + `DEFAULT_STATE` const | `PipelineSettingsPageGeneralState` |
| Query hook | `useXQuery`, `useSuspenseXQuery`, `useXInfiniteQuery`, `useXMutation` | `useGetPipelineQuery`, `useSuspenseListPipelinesInfiniteQuery`, `useDeletePipelineMutation` |

## Imports

Biome sorts imports into groups, blank line between each, in this order. Write them this way and `pnpm format` keeps them.

```tsx
import { useMemo, useState } from "react";

import { create } from "@bufbuild/protobuf";
import { styled } from "@linaria/react";
import { PlusIcon } from "@phosphor-icons/react";
import { useNavigate, useSearch } from "@tanstack/react-router";

import Button, { ButtonVariant } from "@galaxy-io/dls/buttons/Button";
import Flex, { AlignItems, FlexDirection } from "@galaxy-io/dls/layout/Flex";
import { t } from "@galaxy-io/dls/theme/tokens/t";

import { GetPipelineRequestSchema, type Pipeline } from "@/gen/ingestion/v1/pipelines_pb";

import PipelineName from "@/components/PipelineName";

import EmptyLayout from "@/layouts/EmptyLayout";

import { formatPipelineName } from "@/pages/pipelines/utils";

import { useSuspenseGetPipelineQuery } from "@/api/queries/pipelines";

import { useConfirm } from "@/hooks/useConfirm";

import { formatTimeAgo } from "@/utils/format";
```

- Always the `@/` alias. Relative imports only for a sibling `columns/` folder and even then `@/` is preferred.
- DLS by subpath, default export plus its enums from the same module. Never a barrel, never `@galaxy-io/dls` alone.
- `import type` for types. Biome enforces it.

## Types come from the protos

- A prop, state field, param or `Record` key that carries a proto field uses an **indexed access type**. `Pipeline["id"]`, `Connection["connector"]`, `RunInfo["runId"]`, `Record<Connection["id"], WriteMode>`. Display strings and generic components stay `string`.
- **Proto enums are used directly.** `z.enum(ConnectorKind)` in a search schema, `Record<RunStatus, …>` for a map, `ConnectorKind.SOURCE | ConnectorKind.SINK` to narrow. Numeric wire values in a URL are fine. No readable-name codecs, no `Exclude<…, "UNSPECIFIED">` gymnastics.
- **`UNSPECIFIED` is handled by behaviour, not types.** A selector treats it as "all kinds", a flow that needs a kind redirects to the chooser.
- **Enum-keyed maps are exhaustive `Record`s**, never `Partial`. When a member has no value, write the entry with `null` or `undefined` so a new enum member is a type error.
- A list of enum members is derived, `Object.values(RunStatus).filter(…)`, not hand typed.
- **A proto message is the state when the form is shape-identical to it.** `workerResources: WorkerResources` as the state type, `create(WorkerResourcesSchema)` for the empty default (proto3 scalars default to `""` and `0`), `Partial<WorkerResources>` for a patch. A hand-rolled state interface earns its place only when it genuinely decomposes the message (a schedule state that splits a cron string into fields).

## State doctrine

- **Page and component state is one object.** `interface XState { … }`, `const DEFAULT_STATE: XState = { … }`, `useState<XState>(DEFAULT_STATE)` and `setState((prev) => ({ ...prev, field }))` inside `handleX` functions. Not a `useState("")` per field.
- **Initial state from data is a function.** `const createInitialState = (): XState => ({ ...DEFAULT_STATE, name: pipeline.name })`, passed to `useState(createInitialState)` and reused by `handleCancel`. Reset from outside by giving the component a `key`, never by an effect.
- **No `useEffect` in components.** Business logic lives in reducers and handlers. An effect is allowed only inside a named single-purpose hook that syncs a real external system (a ResizeObserver, scroll position, a debounced write to the URL or `localStorage`, the xyflow instance). The few that exist (`MainLayoutListPage` debouncing search into the URL, `PipelinesTable` persisting column layout, `InfiniteScrollSentinel`) are that kind.
- **Derived data is computed at render**, with `useMemo` when it is expensive. It is never stored in state.
- **Maps over ternaries and lookups.** An enum-keyed ternary (`isSink ? A : B`) becomes an `X_TO_Y_MAP` const. A pure lookup function becomes a map. Boolean guards and discriminant-narrowing branches stay as code.
- **Branch per enum member with `match`.** `match(step).with(Step.A, () => …).with(Step.B, () => …).exhaustive()` from `ts-pattern`, so a new member fails to compile.
- **Shared page view state lives in the URL**, not in a context. Timeframes, filters, pivots, the open drawer, the active settings panel are search params. See [routing.md](./routing.md).
- **Providers follow one contract** when a surface needs a reducer (the canvas, the create-pipeline modal, the connection form). Four files in one folder, `XProvider.tsx` (contexts with `displayName`, accessor hooks that throw outside the provider, a memoised derived value), `actions.ts` (an `enum XActionType` and a discriminated union of action interfaces, nothing else), `reducer.ts` (one pure function per action and a delegating `switch`, zero casts), `types.ts` (`XState`, `XDerivedState`, `DEFAULT_STATE`). Consumers never build `{ type, payload }` objects. The provider exports semantic action functions, or step components call the dispatch hook with actions created next to the enum. The reducer is the only writer and the only enforcer of domain invariants. See [forms.md](./forms.md).

## Styling inside the app

Everything the DLS references say about tokens applies. The app adds a few habits.

- **Reach for `Flex`, `Box`, `Grid`, `FlexItem` props first.** `gap`, `padding`, `fillWidth`, `height="100%"`, `minWidth={0}`, `grow`, `shrink`, `overflow` cover most layout. A `styled` component appears when props cannot express it, a fixed-size frame (`IconTile`), a scroll region with its own padding (`MainLayoutListPageScrollArea`), absolute positioning (`PreviewChipOverlay`), a custom interactive element (`SidebarButton`, `AvatarButton`).
- **Styled components are wrappers, named for what they wrap.** `PipelinesTableWrapper`, `MainLayoutIslandWrapper`, `ContentIsland`. Two or three per file at most, declared above the component.
- **`styled` from `@linaria/react`, `t` from `@galaxy-io/dls/theme/tokens/t`, mixins from `@galaxy-io/dls/styles/mixins`.** `HAIRLINE_WIDTH` for every border width, `INTERACTIVE_RESET` + `FOCUS_RING` on any hand-made button.
- **`$`-props only for continuous values** (`$size`, `$width`, `$isActive` for a single boolean). An enum axis is a `Record<Enum, string>` of `css` blocks, or two styled components. Linaria cannot interpolate a CSS property name from a prop.
- **The island.** Filament's pages sit on `background.base` and content lives in an island, `background.primary` with a `HAIRLINE_WIDTH solid border.primary` border and `t.radius.lg` corners, `overflow: hidden`. `MainLayout`, `PipelineLayout` and the settings modal all draw it. New full-page surfaces do the same rather than inventing a frame.
- **Pixel constants are named.** `MAIN_LAYOUT_GUTTER = 12`, `PIPELINE_SIDEBAR_WIDTH = 48`, `PIPELINE_NAVBAR_HEIGHT = 48`, column widths in the table's `constants.ts`. Never a bare number in a template that another file also needs.
- **Editing a constant used inside a `styled` template does not hot-reload.** Linaria compiles the template once and the Vite plugin does not watch the constant's module. Touch or edit the component file to re-transform it, then check the computed style.
- **No margins, no hex, no inline `style` except CSS custom properties.** Biome's DLS rules fail the build on these.

## Minimalism, the way the codebase wants it

- No loader, helper hook, lookup function or wrapper that does not earn its place. Delete dead code when you find it.
- Write a four-field form as four inputs. A field-config array mapped to inputs is not simpler.
- One caller needs a variant of a shared helper's behaviour. Add an optional defaulted argument to the helper (`formatPipelineName(pipeline, includeDeleted = false)`), do not branch at the call site.
- Shared components own their copy. Callers pass semantic booleans (`hasStoredSecret`), never free-text strings for labels or placeholders.
- Build the reusable piece in the home where its data already lives, and migrate the existing one-offs in the same change. `PipelineRunStatusSwatch` sits beside `PIPELINE_RUN_STATUS_TO_HUE_MAP`, and the notifier form's one-off status dot was replaced by it in the change that created it.
- "Boring default" beats clever cache surgery. Invalidate queries, do not seed them.
