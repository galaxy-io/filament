# Routing and URL state

Filament uses TanStack Router with file-based routes. The URL is the app's shared state. A screen's filters, sort, open drawer, active panel and selection all live in search params, so a link reproduces the screen and the back button works.

## The route tree

```
src/routes
├── __root.tsx                    beforeLoad fetches GetAuthConfig; RootErrorComponent ("Could not reach the server")
├── login.tsx · register.tsx · invite.$token.tsx    the auth shell, redirect to "/" when auth is off
├── _app/
│   ├── route.tsx                 the session gate + the app-wide overlay search params; component = AppLayout
│   ├── _main/
│   │   ├── route.tsx             <MainLayout><Outlet /></MainLayout>  (navbar with tabs + the island)
│   │   ├── index.tsx             redirect → /observability
│   │   ├── observability.tsx     dashboard view state (timeframe, pivots, statuses, sort)
│   │   ├── pipelines.tsx         listSearchParamsSchema (q, sortBy, sortOrder) + remountDeps
│   │   ├── sources.tsx           listSearchParamsSchema.pick({ q }) → <ConnectionsPage kind={SOURCE} />
│   │   └── sinks.tsx             same with SINK
│   └── pipelines/
│       ├── $id.tsx               version param, errorComponent that maps NotFound, component = PipelinePage (renders PipelineLayout)
│       └── $id/
│           ├── index.tsx         redirect → canvas
│           ├── canvas.tsx        node, resource, showPanel, tab
│           ├── history.tsx       runId[]
│           └── settings.tsx
```

- `_app` and `_main` are pathless layout routes. Everything under `_app` has a session in route context. Everything under `_main` renders inside the main navbar and island. A pipeline detail route sits outside `_main` because it has its own shell (`PipelineLayout`).
- `routeTree.gen.ts` is generated by the Vite plugin while `pnpm dev` or `pnpm build` runs and is committed. After adding a route file, run the dev server (or `pnpm build`) and commit the regenerated tree. `git diff --exit-code src/routeTree.gen.ts` is one of the gates.
- `router.tsx` sets `defaultPreload: "intent"`, `defaultPreloadStaleTime: 0`, and the three default components. `defaultPendingComponent` is `PendingLayout`, `defaultErrorComponent` is an `ErrorLayout` with `BugIcon`, `defaultNotFoundComponent` is an `ErrorLayout` with a "Go back to app" button.

## A route file does one thing

A route file declares the `Route` and nothing else. No data fetching, no layout, no styled components.

```tsx
import { createFileRoute } from "@tanstack/react-router";
import z from "zod";

import PipelineHistoryPage from "@/pages/pipelines/PipelineHistoryPage";

const searchParams = z.object({
  runId: z.array(z.string()).optional().catch(undefined),
});

export const Route = createFileRoute("/_app/pipelines/$id/history")({
  validateSearch: searchParams,
  component: PipelineHistoryPage,
});
```

What a route may set.

| Option | When |
|---|---|
| `validateSearch` | The route reads any search param. See below. |
| `component` | The `*Page.tsx`, or an inline arrow that passes a prop (`() => <ConnectionsPage kind={ConnectorKind.SOURCE} />`). |
| `remountDeps` | A list page whose suspense query should re-suspend when the search changes. `remountDeps: ({ search: { q, sortBy, sortOrder } }) => ({ q, sortBy, sortOrder })`. |
| `beforeLoad` | Redirects (`throw redirect({ to: "/observability" })`) and auth gates only. Never data for the page. |
| `errorComponent` / `notFoundComponent` | A detail route that wants its own "not found" (`$id.tsx` maps `ConnectError` with `Code.NotFound` to `PipelineNotFoundComponent` and falls back to `DefaultErrorComponent`). |

There are **no loaders**. Pages fetch with suspense hooks and the router's pending component covers the first paint. This is a deliberate trade for a thinner stack. If you ever add one, note that `queryClient.ensureQueryData` returns cached data regardless of staleness, so the loader will not refetch after a mutation unless you pass `revalidateIfStale: true`.

## Search params

Every search param is declared with zod in the route that **reads** it.

```ts
const searchParams = z.object({
  timeframe: z.enum(ObservabilityTimeframe).optional().catch(undefined),
  statuses: z.array(z.enum(RunStatus)).optional().catch(undefined),
  runsBucket: z.coerce.bigint().positive().optional().catch(undefined),
  sortBy: z.enum(SortBy).optional().catch(undefined),
});
```

- **Every field is `.optional().catch(undefined)`.** Garbage in the URL becomes `undefined`, never a crash and never a hand-written coercion.
- **Proto enums go in directly**, `z.enum(RunStatus)`. Numeric wire values in the URL are fine. Local string enums the same way, `z.enum(Flow)`.
- **Defaults are applied where the value is read**, not in the schema, so the URL stays clean. `const { timeframe = ObservabilityTimeframe.TWENTY_FOUR_HOURS } = useSearch({ from: "/_app/_main/observability" })`.
- **A value that equals the default is written as `undefined`** so it disappears from the URL. `showPanel: next || undefined`, `tab: nextTab === Tab.OVERVIEW ? undefined : nextTab`. When "explicitly none" must be distinguishable from "default", store the proto `UNSPECIFIED` member.
- **Shared list params** come from `listSearchParamsSchema` in `src/api/utils.ts` (`q`, `sortBy`, `sortOrder`). A route that only searches picks `q`. `createListSearchInput(search)` turns them into the request's `search` and `sorting` fields.
- **`bigint` params** use `z.coerce.bigint().positive()`. They round-trip because `src/utils/serialization.ts` patches `BigInt.prototype.toJSON`.

### Reading

```tsx
const { id } = useParams({ from: "/_app/pipelines/$id" });
const search = useSearch({ from: "/_app/_main/pipelines" });
const { runId: runIds = [] } = useSearch({ from: "/_app/pipelines/$id/history" });
const { session } = useRouteContext({ from: "/_app" });
```

- Always pass `from` with the full route id. A child component reads its parent's params with the parent's id (`useParams({ from: "/_app/pipelines/$id" })` inside a settings section).
- **Declare a param on the route where it is read, not only where it is written.** `useSearch({ strict: false })` returns the nearest match's search, and a param validated only on a child arrives raw in a parent while TypeScript still claims the validated type. `version` once compared `1n === 1` for this reason and was lifted to `$id.tsx`. The only `strict: false` reads left are for `q`, whose raw and validated types are both `string`, in `MainLayoutListPage` and `ConnectionsPage` because they serve several routes.

### Writing

```tsx
const navigate = useNavigate();

void navigate({
  to: ".",
  search: (prev) => ({ ...prev, timeframe, runsBucket: undefined, runsStatus: undefined }),
});

void navigate({
  to: ".",
  replace: true,
  search: (prev) => ({ ...prev, q: debouncedSearch || undefined }),
});

void navigate({ to: "/pipelines/$id/history", params: { id: run.pipelineId }, search: { runId: [run.id] } });
```

- **Always the functional form that spreads `prev`.** A write never drops params it does not own.
- **`replace: true` for view state** (search text, sort, expansion, canvas selection) so the back button does not walk through every keystroke. Push for navigation the user would want to return to (opening a drawer, changing a dashboard timeframe).
- **Clear by writing `undefined`**, or rest-destructure the keys out when closing a flow.
- **A parent filter clears its dependents.** Changing the timeframe clears the selected bucket and status. Opening one overlay clears the others (`connectionId: undefined` when opening a flow).
- Prefix with `void`. Navigation returns a promise nobody awaits.
- Typed route ids and params everywhere. `useRouteMatch({ route: "/pipelines/$id/history" })` (from `src/hooks/useRouteMatch.ts`) tells a nav item whether it is active. `RouterLink` (`src/components/RouterLink.tsx`) adapts `Link` so DLS components can take `as={RouterLink}` with an `href` (the main navbar `Tabs`).

## Pending, error and not found

- A page that fetches with suspense hooks shows the router's `PendingLayout` on a cold load. Nothing to write.
- A detail page whose entity came back empty throws `notFound()` from `@tanstack/react-router` after its hooks. The nearest `notFoundComponent` renders an `ErrorLayout` with an icon, a header, a message and a way back.
- A route whose RPC can return `Code.NotFound` gives the route an `errorComponent` that checks `error instanceof ConnectError && error.code === Code.NotFound` and otherwise defers to `DefaultErrorComponent` from `src/router.tsx`.
- The root `RootErrorComponent` has a Retry button that calls `router.invalidate()`.

## Auth in the tree

- `__root` `beforeLoad` fetches `GetAuthConfig` once (`PROBE_QUERY_OPTIONS`, never refetched) and puts `authConfig` in context.
- `_app` `beforeLoad` returns `DEFAULT_SESSION` when `authConfig.issuer` is empty (auth disabled), otherwise fetches `GetSession` and redirects to `/login?returnTo=` **only** on `Code.Unauthenticated`. Any other error propagates, so an identity-provider outage renders the root error instead of a login page that blames the user.
- Pages read the session with `useRouteContext({ from: "/_app" })`. `session.isAuthenticated`, `session.userId`, `session.name`. Seed avatars from `session.userId`, never from email or name.
- `useSignOut` (`src/auth/hooks/useSignOut.ts`) calls the Logout RPC, navigates to `/login` with `replace`, then clears the query client.

## URL-driven overlays

Overlays that can open from anywhere in the app are not routes and not local state. They are search params on `/_app`, and `AppLayout` renders them once above the `Outlet`.

```ts
// routes/_app/route.tsx
const searchParams = z.object({
  connectionId: z.string().optional().catch(undefined),     // the connection drawer
  flow: z.enum(Flow).optional().catch(undefined),           // CREATE_CONNECTION | EDIT_CONNECTION | CREATE_PIPELINE | SETTINGS
  connectorKind: z.enum(ConnectorKind).optional().catch(undefined),
  connector: z.string().optional().catch(undefined),
  connectorSearch: z.string().optional().catch(undefined),
  settings: z.enum(SettingsPanel).optional().catch(undefined),
  teamView: z.enum(TeamSettingsView).optional().catch(undefined),
  inviteToken: z.string().optional().catch(undefined),
});
```

```tsx
// layouts/app/AppLayout.tsx
const { connectionId, flow } = useSearch({ from: "/_app" });
const isDrawerOpen = !!connectionId;
const drawerConnectionId = useRetainedWhileClosed(connectionId, isDrawerOpen);

return (
  <>
    <Outlet />
    <ConnectionDrawer connectionId={drawerConnectionId} isOpen={isDrawerOpen} onClose={handleCloseDrawer} />
    {flow === Flow.CREATE_CONNECTION && <CreateConnectionModal onClose={handleCloseFlow} />}
    {flow === Flow.CREATE_PIPELINE && <CreatePipelineModal onClose={handleCloseFlow} />}
    <SettingsPage />
  </>
);
```

Rules that keep this working.

- **Add a new app-wide overlay as a `Flow` member** (`layouts/app/types.ts`) plus whatever params it needs, declared on `/_app`. Render it in `AppLayout`. Open it with `navigate({ to: ".", search: (prev) => ({ ...prev, flow: Flow.X }) })` from anywhere.
- **Overlay content must not read search params.** A DLS Drawer or Modal keeps rendering for 150ms after `isOpen` flips while it animates out, and a descendant that calls `useSearch` re-renders with the param already gone (the "flash of No pipelines" bug). The component that owns `isOpen` reads the params, holds the last value with `useRetainedWhileClosed(value, isOpen)` (`src/hooks/useRetainedWhileClosed.ts`), and passes it down as a prop.
- **Keep the overlay mounted and drive `isOpen`** so it animates and restores focus. The create modals are the exception, mounted conditionally so their reducer state resets per open, and they get no exit animation as a result.
- **Closing strips only the keys the overlay owns**, by rest-destructuring, so a drawer closing does not also close a modal.
- **One overlay at a time.** Opening a flow writes `connectionId: undefined`.
- Nothing rendered under `__root` outside a route (the drawer, the modals, settings) may use a suspense hook. The only suspense boundary above them is the app-wide one. They use plain queries with `isLoading` and `isError` branches. See [data.md](./data.md).
