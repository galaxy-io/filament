# Routing and URL state

Filament uses TanStack Router. The URL is the app's shared state. A screen's filters, sort, open drawer, active panel and selection all live in search params, so a link reproduces the screen and the back button works.

Library code never knows where it is mounted. The standalone mounts it at `/`, a Galaxy host mounts it under a path such as `/ingest`. Everything on this page follows from that.

## The pieces

| Piece | File | Job |
|---|---|---|
| `FilamentPath` | `module/paths.ts` | the only module-relative path strings (`"./pipelines/$id/canvas"`) |
| `createFilamentHref(path, params)` | `module/paths.ts` | fills `$params` for an `href` |
| `*RouteOptions` | `module/routes.tsx` | what each route needs (search schema, `remountDeps`, pending, error, not found) |
| schemas | `module/schemas.ts` | every search schema and the one params schema |
| read and write hooks | `module/hooks.ts` | the only callers of `useSearch`, `useParams` and `useNavigate` in library code |
| file routes | `host/routes/**` | the standalone's tree, each file spreads one `*RouteOptions` |

## The standalone route tree

```
src/host/routes
├── __root.tsx                       beforeLoad fetches GetAuthConfig, RootErrorComponent ("Could not reach the server")
├── login.tsx · register.tsx · invite.$token.tsx
└── _app/
    ├── route.tsx                    the session gate, component = AppLayout (Outlet + command palette)
    └── _filament/
        ├── route.tsx                ...filamentLayoutRouteOptions, FilamentLayout with the account menu as sidebarFooter
        ├── index.tsx                redirect → /observability
        ├── $.tsx                    ...filamentNotFoundRouteOptions, NotFoundPage
        ├── observability.tsx · pipelines/index.tsx · sources.tsx · sinks.tsx
        ├── pipelines/$id.tsx        ...pipelineRouteOptions, PipelinePage
        ├── pipelines/$id/index.tsx  redirect → canvas
        ├── pipelines/$id/canvas.tsx · history.tsx · settings.tsx
        └── settings/team.tsx · service-accounts.tsx    standalone only
```

- `_app` and `_filament` are pathless layout routes. Everything under `_app` has a session in route context.
- `src/host/routeTree.gen.ts` is generated by the router plugin during `pnpm dev` and `pnpm build`, and committed. `git diff --exit-code src/host/routeTree.gen.ts` is a gate.
- `host/router.tsx` sets `defaultPreload: "intent"`, `defaultPreloadStaleTime: 0`, and Filament's pending and error components as defaults for the routes outside the module (`login`, the root).

## A route file does one thing

A route file spreads the module's options and names the page. No data, no layout, no styled components.

```tsx
import { createFileRoute } from "@tanstack/react-router";

import PipelinePage from "@/pages/pipelines/PipelinePage";

import { pipelineRouteOptions } from "@/module/routes";

export const Route = createFileRoute("/_app/_filament/pipelines/$id")({
  ...pipelineRouteOptions,
  component: PipelinePage,
});
```

Index redirects are host files with absolute paths, because only the host knows the mount.

```tsx
export const Route = createFileRoute("/_app/_filament/")({
  beforeLoad: () => {
    throw redirect({ to: "/observability" });
  },
});
```

## Route options

Every exported page, the layout and the splat get one `*RouteOptions`, built by the private `createFilamentRouteOptions` in `module/routes.tsx`.

```tsx
const createFilamentRouteOptions = <TOptions extends object>(options: TOptions) => ({
  errorComponent: FilamentErrorComponent,
  pendingComponent: FilamentPendingComponent,
  ...options,
});

export const pipelinesRouteOptions = createFilamentRouteOptions({
  validateSearch: pipelinesSearchSchema,
  remountDeps: ({ search }: { search: PipelinesSearch }) => ({
    q: search.q,
    sortBy: search.sortBy,
    sortOrder: search.sortOrder,
  }),
});
```

| Option | When |
|---|---|
| `validateSearch` | the route owns search params |
| `remountDeps` | a list page whose suspense query must re-suspend when its list params change |
| `errorComponent` / `notFoundComponent` | `pipelineRouteOptions` maps `Code.NotFound` to `PipelineNotFoundPage` through `PipelineErrorComponent` |
| `staticData: { filament: true }` | the layout only, so `useFilamentMountedBase` can find the mount |

A new page means a new `*RouteOptions`, a host file in `host/routes/`, a route in `fixtures/host/router.tsx`, and an `./pages/<Page>` entry in `package.json` `exports` if hosts may mount it.

There are **no loaders for page data**. The standalone's auth gates in `beforeLoad` are the only `ensureQueryData` calls. Pages fetch with suspense hooks and the route's pending component covers the first paint. If you ever add one, `queryClient.ensureQueryData` returns cached data regardless of staleness, so a loader does not refetch after a mutation unless you pass `revalidateIfStale: true`.

## Search params

Schemas live in `module/schemas.ts`.

```ts
export const observabilitySearchSchema = listSearchParamsSchema
  .pick({ sortBy: true, sortOrder: true })
  .extend({
    timeframe: z.enum(ObservabilityTimeframe).optional().catch(undefined),
    statuses: z.array(z.enum(RunStatus)).optional().catch(undefined),
    runsBucket: z.coerce.bigint().positive().optional().catch(undefined),
    runsStatus: z.enum(RunStatus).optional().catch(undefined),
  });
```

- **Every field is `.optional().catch(undefined)`.** Garbage in the URL becomes `undefined`, never a crash.
- **Proto enums go in directly**, `z.enum(RunStatus)`. Local string enums the same way, `z.enum(Flow)`.
- **The one params schema** is `pipelineParamsSchema = z.object({ id: z.string() })`, read only under `$id`.
- **Shared list params** come from `listSearchParamsSchema` (`q`, `sortBy`, `sortOrder`). A route that only searches picks `q`.
- **`bigint` params** use `z.coerce.bigint().positive()`. The router writes primitives with `String`, so they round-trip without any global patch.
- **Defaults never live in the schema.** They apply in the read hook, so the URL stays clean.
- **A value that equals the default is written as `undefined`** so it disappears from the URL. When "explicitly none" must differ from "default", store the proto `UNSPECIFIED` member.

## Reading

Library code reads only through `module/hooks.ts`. Each read hook parses with its schema in `select`, so the value is typed by the schema and never cast.

```ts
export const usePipelineCanvasSearch = () =>
  useSearch({
    strict: false,
    structuralSharing: true,
    select: (search) => pipelineCanvasSearchSchema.parse(search),
  });

export const useObservabilitySearch = () =>
  useSearch({
    strict: false,
    structuralSharing: true,
    select: (search) => {
      const parsed = observabilitySearchSchema.parse(search);
      return { ...parsed, timeframe: parsed.timeframe ?? OBSERVABILITY_DEFAULT_TIMEFRAME };
    },
  });
```

| Hook | Reads |
|---|---|
| `useFilamentLayoutSearch` | the overlay params (`flow`, `connectionId`, `connectorKind`, `connector`, `connectorSearch`) |
| `useListSearch`, `usePipelinesSearch`, `useConnectionsSearch` | list params |
| `useObservabilitySearch` | dashboard view state, with defaults applied |
| `usePipelineSearch`, `usePipelineCanvasSearch`, `usePipelineHistorySearch` | `version`, the canvas selection, expanded runs |
| `usePipelineParams` | `{ id }` under `$id` |
| `useTeamSearch` | the standalone Team page |

`strict: false` returns the nearest match's raw search, which is why parsing in `select` matters. A parent reading a child's param gets a parsed value, not a raw string that TypeScript claims is validated. The host session is the exception, read with `useRouteContext({ from: "/_app" })` in `src/host/**`.

## Writing

```tsx
const updateSearch = useFilamentSearchUpdate<FilamentLayoutSearch>();
void updateSearch((prev) => ({ ...prev, connectionId: connection.id }));

const navigate = useFilamentNavigate();
void navigate({ to: FilamentPath.PIPELINE_HISTORY, params: { id }, search: { runId: [run.id] } });
```

- **`useFilamentSearchUpdate`** writes search on the current route. Always the functional form that spreads `prev`, so a write never drops params it does not own.
- **`useFilamentNavigate`** navigates from the mount base to a `FilamentPath`. `useFilamentFlowOpen` opens a `Flow` from anywhere, clearing `connectionId`.
- **`useFilamentMatchRoute`** tells a nav item whether it is active.
- **Links** use `createFilamentHref(path, params)` with `as={RouterLink}` on DLS components. `RouterLink` (`components/RouterLink.tsx`) adapts `Link` so DLS buttons and tabs take an `href`.
- **`replace: true` for view state** (search text, sort, expansion, canvas selection) and for closing overlays. Push for navigation the user would want to return to.
- **A parent filter clears its dependents.** Changing the timeframe clears the selected bucket and status.
- Prefix with `void`. Navigation returns a promise nobody awaits.

Never write an absolute path (`to: "/pipelines"`) or a route id (`from: "/_app/…"`) in library code. The §4.5 greps fail on both.

## Pending, error and not found

- A page that suspends shows `FilamentPendingComponent` (DLS `PendingLayout`) from its route options.
- A render or query error shows `FilamentErrorComponent`, a red `ErrorLayout` with `BugIcon`, "Looks like there was a glitch in the matrix", and `detail` in debug builds.
- A pipeline that does not exist shows `PipelineNotFoundPage`, through `notFoundComponent` and through `PipelineErrorComponent` on `Code.NotFound`.
- An unknown path under the mount hits the `$` splat and shows `NotFoundPage`, a red `ErrorLayout` with RouterLink buttons.
- The host's query client should skip retries for `NotFound`, `PermissionDenied`, `Unauthenticated`, `InvalidArgument` and `Unimplemented`. Otherwise a missing pipeline retries for about 7s before its not-found page. The standalone's `host/api/queryClient.ts` does this.

## Auth in the tree (standalone only)

- `__root` `beforeLoad` fetches `GetAuthConfig` once and puts `authConfig` in context.
- `_app` `beforeLoad` returns `DEFAULT_SESSION` when `authConfig.issuer` is empty, otherwise fetches `GetSession` and redirects to `/login?returnTo=` **only** on `Code.Unauthenticated`. Any other error propagates, so an identity-provider outage renders the root error instead of a login page that blames the user.
- Host code reads the session with `useRouteContext({ from: "/_app" })`. Seed avatars from `session.userId`, never from email or name.
- `useSignOut` (`host/auth/hooks/useSignOut.ts`) calls the Logout RPC, navigates to `/login` with `replace`, then clears the query client.
- Library code never reads the session. A library surface that depends on permissions asks the API (`useCanManageTeam`), and gates its query with `enabled` so a signed-out view sends nothing.

## URL-driven overlays

Overlays that open from anywhere are search params on the layout route, rendered once by `FilamentLayout` beside the `Outlet`.

| Param | Opens |
|---|---|
| `connectionId` | the connection drawer |
| `flow=CREATE_CONNECTION` (+ `connectorKind`, `connector`, `connectorSearch`) | the create-connection modal |
| `flow=EDIT_CONNECTION` + `connectionId` | the edit-connection modal over the drawer |
| `flow=CREATE_PIPELINE` | the create-pipeline modal |

```tsx
<ConnectionDrawer connectionId={connectionId} isOpen={!!connectionId} onClose={handleCloseDrawer} />
<CreatePipelineModal isOpen={flow === Flow.CREATE_PIPELINE} onClose={handleCloseFlow} />
```

Rules that keep this working.

- **Add an overlay as a `Flow` member** (`module/types.ts`) plus its params in `filamentLayoutSearchSchema`, render it in `FilamentLayout`, open it with `useFilamentFlowOpen`.
- **Overlays stay mounted and take their record as props.** Only `FilamentLayout` reads the params. DLS Drawer and Modal keep their last children through the exit animation, so content that never reads the URL never flashes.
- **Each open is a new session.** `useOverlaySession(isOpen)` returns a key that changes on every open. Key the overlay's provider with it so state resets per open while the exit still animates.
- **An overlay that picks between two `Modal`s from a URL record** holds the record through the exit with `useOverlayRecord(isOpen, value)`, because closing strips the record in the same navigation.
- **Closing strips only the keys the overlay owns**, by rest-destructuring, with `replace: true`.
- **One overlay at a time.** Opening a flow writes `connectionId: undefined`.
- Overlays use plain queries with `isLoading` and `isError` branches, never suspense. See [data.md](./data.md).
