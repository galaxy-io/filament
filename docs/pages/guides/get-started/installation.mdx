Choose the option that matches what you are trying to do:

| Option | Best for | State |
|---|---|---|
| Standalone binary | Trying Filament locally | In memory; lost on restart |
| Go library | Adding replication to a Go service | Chosen by the host application |
| Kubernetes | Running separate API, control-plane, and worker processes | Postgres and NATS |

Container images for every binary are published at
`ghcr.io/galaxy-io/filament/{server,control-plane,worker,standalone}`.

## Standalone binary

The fastest way to try Filament. One process bundles everything:

- An embedded NATS JetStream (no ports exposed)
- An in-memory data store
- Env-var secrets
- The embedded web app
- A curated connector set (`clickhouse`, `iceberg`, `mysql`, and `postgres`)

Runs execute in-process. It listens on `INGESTION_ADDR`, default `:8080`.

```sh
docker run -p 8080:8080 ghcr.io/galaxy-io/filament/standalone
```

<Warning>
  The standalone binary keeps all state (connections, pipelines, runs,
  checkpoints) in memory. Nothing survives a restart. Use it to evaluate,
  not to operate.
</Warning>

Secrets come from environment variables. A ref like `postgres-creds/dsn`
reads the env var `POSTGRES_CREDS_DSN`. JetStream state is stored in
`NATS_STORE_DIR` (default `$TMPDIR/filament-standalone`) and the SQLite
datastore in `STORE_PATH` (default `filament.db` in that directory).

## As a Go library

Filament embeds directly via `app.Run`. Connectors self-register through
blank imports, so you only pull in the ones you use. The defaults are an
in-process bus and an in-memory store. The API (and optionally the UI) is
served on `INGESTION_ADDR` (`:8080`), and runs execute in-process.

```go
package main

import (
	"context"
	"log"

	"github.com/galaxy-io/filament/app"
	_ "github.com/galaxy-io/filament/connectors/postgres"
	_ "github.com/galaxy-io/filament/connectors/stdout"
)

func main() { log.Fatal(app.Run(context.Background())) }
```

See [Embedded](/pages/guides/usage/embedded)
for swapping in NATS, Postgres, and a real secrets provider.

## On Kubernetes

The Helm chart deploys the server and control plane, dispatches each run as
its own Job, and points at your Postgres and NATS instances (or provisions
optional vendored subcharts for evaluation). See
[Kubernetes](/pages/guides/deployment/kubernetes) for the install steps.

## Building from source

`just binaries` builds every binary into `bin/filament/` and compiles
`server`, `standalone`, and `cli` with the `embedui` build tag so the
web app is embedded. A plain `go build` of those binaries serves a placeholder page
instead of the UI, so use `just binaries` (or pass `-tags embedui` yourself)
when you want the UI in the binary. `just images` builds the container
images.
