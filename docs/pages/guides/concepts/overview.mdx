Filament has a small object model. Learn these and the rest of the docs reads
easily.

- A **connection** is a configured connector, either a source to read from or
  a sink to write to. It holds credentials and the settings that describe
  reaching that system, saved once and reused.
- A **pipeline** is a graph of connections. Its edges route resources from a
  source to a sink, and each edge carries a read mode, a write mode, and a
  cursor where one is needed. Editing the graph mints a new immutable version.
- A **resource** is one table, stream, or API collection inside a source.
- A **run** is one execution of a pipeline route. It is the unit that gets
  scheduled, tracked, verified, and resumed.

## What happens during a run

Every run takes the same path regardless of where it was dispatched from.

1. The run is requested and persisted, then picked up by whichever dispatch
   backend the deployment uses.
2. Connectors are resolved and configured, resources are planned, and each
   resource is bound to a write policy compiled from its read and write modes.
3. Checkpoints are seeded so a resumable run knows where to start.
4. Records flow from the source through batching into the sink, with each
   batch checksummed on both sides before it counts as written.
5. The run publishes facts as it goes. State is derived from those facts
   rather than written directly.
6. On success the sink commits and cursors become durable. On failure the run
   either fails outright or lands in a partial state that a later run
   continues from.
