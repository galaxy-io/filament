## Formatting and linting

Go code is formatted with `gofumpt` (extra rules enabled) and `goimports` with
the repository's local import prefix, both driven through `golangci-lint fmt`.
The linter set in `.golangci.yaml` includes `staticcheck`, `gosec`,
`errcheck`, `govet`, `prealloc`, `ineffassign`, `gocritic`, `revive`,
`misspell`, `gocyclo`, `funlen`, `unused`, and `unparam`. The UI is formatted
and linted by Biome, and protobuf definitions by `buf format` and `buf lint`.

One pair of commands covers all of it. The check variant is a mode argument,
not a separate recipe:

```sh
just format          # fix formatting: Go, UI, proto
just format check    # verify without writing
just lint            # run linters with --fix
just lint check      # verify without fixing
```

CI runs the granular recipes (`just go-lint check`, `just go-format check`,
`just ui-lint check`, `just ui-format check`) plus `buf lint` and a
`proto-check` that fails if regenerating stubs would change checked-in files.

## Testing

There are three layers of tests, run by two commands.

**`just test`** runs the unit tier, which covers every Go module except
`tests/`, with no build tags and no Docker anywhere. This covers plan compilation, the pipeline
(batching, divergence and write-error fatality, checkpoint publication, CRC
regrouping detection), event bus, checkpoint, connector, datastore, runner,
secret, and server packages.

**`just test-integration`** runs the `tests/` module, which holds both the
integration and e2e layers, since every file there carries
`//go:build integration`. It needs Docker (testcontainers spin up PostgreSQL,
NATS, MinIO, Trino, k3s, and others) and `duckdb` on your PATH. TPC-H seeding
hard-fails without it.

<Warning>
Running `go test ./...` in `tests/` without `-tags integration` matches no
packages and exits 0 — it passes while testing nothing. Use
`just test-integration`, which passes the tag.
</Warning>

### What the suites prove

The integration suite exercises the guarantees the engine claims:

- The resume matrix kills runs mid-extract and injects concurrent writes into
  the fail-to-resume window, treating any row LOSS as failure and DUPLICATE
  rows as acceptable (at-least-once).
- ctid reconcile verifies horizon reconciliation and the rewrite guard.
- The NATS durable-consumer tests verify consumers survive restarts.
- The k8s dispatch tests assert the exact worker Job spec and dispatch
  idempotency against a real API server in a k3s container.
- The reaper tests verify stale runs get failed.
- An Iceberg sink test writes from PostgreSQL through a REST catalog to MinIO
  and verifies the result with an independent Trino reader.

The e2e layer runs two full flows. The first pushes TPC-H data through
JetStream from PostgreSQL to Iceberg, Trino-verified. The second drives the
complete control-plane path through the Connect API, with connections,
pipeline, run, and row-count assertions across two PostgreSQL containers.

## Benchmarks

Go benchmarks exist for the pipeline hot path and the in-process event bus.
They are manual-only, with no justfile recipe, and never run in CI:

```sh
go test -bench=. -benchmem ./pipeline/...
go test -bench=. -benchmem ./eventbus/...
```

What they measure and how to read them is covered in the
[Benchmarks](/pages/benchmarks/overview).
