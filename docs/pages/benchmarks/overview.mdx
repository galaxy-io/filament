Filament is benchmarked in the open. The harness, datasets, methodology, and
results live in a dedicated repository,
[github.com/galaxy-io/benchmarks](https://github.com/galaxy-io/benchmarks),
so runs can be reproduced and audited independently of this codebase.

## Data movement

The primary benchmark measures full loads of TPC-H or NYC Taxi data. It tests
PostgreSQL and MySQL sources against PostgreSQL, MySQL, and Iceberg
destinations. For example, one case copies the same prepared PostgreSQL dataset
to a fresh MySQL destination with Filament and with comparable tools. Native
database dump-and-load is also measured when source and destination use the
same engine.

The methodology is strict about fairness:

- One unchanged prepared source dataset for each group of comparable runs
- A fresh destination for every repetition, with database services restarted
  before timing
- A settling period and an autovacuum check before the timer starts
- A result counts only when every destination table matches the seed's
  row-count manifest

Each run records timing, effective configuration, endpoint topology, host
details, image IDs, and per-container CPU, memory, and network use. Remote
cohorts on RDS also capture database counters and CloudWatch metrics around
the timed window.

<Info>
  Results, raw data, and instructions for reproducing a run are in the
  [benchmarks repository](https://github.com/galaxy-io/benchmarks). This
  section documents what is measured, not published numbers.
</Info>
