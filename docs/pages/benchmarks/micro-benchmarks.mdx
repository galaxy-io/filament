---
title: "Micro-benchmarks"
description: "The in-repo Go benchmarks that isolate the engine's own overhead"
---

A small set of Go benchmarks lives in the Filament repository. Each isolates
one layer, so the difference between any two rungs attributes overhead
precisely. The null-sink pipeline rung is the engine's floor. Anything a full
run costs above it comes from the source read, the bus, and the tracker.

They are plain Go benchmarks. No Docker, no `just` recipe, and they do not
run in CI. No numbers are published here because results depend on hardware.
Run them yourself:

```sh
go test -bench=. -benchmem ./pipeline/...
go test -bench=. -benchmem ./eventbus/...
```

## Pipeline

`pipeline/pipeline_bench_test.go` pushes pre-built records through the full
batcher, writer, and integrity loop into a null sink. The sink does no I/O
but still recomputes the write-side CRC, so integrity work stays measured.

- `BenchmarkNullSinkPipeline` measures the serial path and reports a
  `records/sec` metric alongside allocations per operation
- `BenchmarkNullSinkPipelineParallel` spreads records across multiple
  resources so batcher sharding engages, and sweeps `SnapshotParallelism`

## Event bus

`eventbus/inproc/inproc_bench_test.go` measures the in-process bus used by
the standalone binary, the library default, and tests. NATS transport is
deliberately out of scope here.

- `BenchmarkPublishNoSubscribers` is the publish floor with nothing listening
- `BenchmarkPublishFanout8` adds draining wildcard subscribers, the realistic
  per-fact cost
- `BenchmarkPublishParallel` contends publishers on the bus mutex

## Profiling

The `profiling` package mounts standard pprof endpoints on any mux and
captures bounded file-based sessions. No shipped binary wires it in, so mount
it yourself where you need it:

```go
go profiling.Serve(ctx, "127.0.0.1:6060")
```
