`connectors/iceberg` (registered as `iceberg`, **alpha**) writes records as
Parquet data files into Apache Iceberg tables through a REST or
[iceberg-go](https://github.com/apache/iceberg-go)-registered catalog. It is
the engine's only transactional sink. `Apply` calls only buffer, and every
catalog and object-store write happens at `Commit` — one Iceberg transaction
per resource, so readers never see a half-written run.

## Configuration

| Field | Scope | Default | Description |
| --- | --- | --- | --- |
| `catalog` | Connection | — | Required. Catalog connection object. See below. |
| `catalog.provider` | Connection | — | Required. `generic`, `rest`, `polaris`, or `lakekeeper`. |
| `table.location_root` | Connection | — | Optional object-storage root for new tables (e.g. `s3://bucket/warehouse`). Leave empty when the catalog assigns locations. |
| `namespace` | Pipeline | `default` | Destination namespace, dot-separated |
| `stage_buffer_limit_mb` | Pipeline | `256` | In-memory buffer threshold in MiB before spilling to temp files |

A `namespace` left empty is defaulted server-side to the normalized source
connection name.

Per provider, inside `catalog`:

| Provider | Fields |
| --- | --- |
| `generic` | `type` or `uri` (either is required). Optional `warehouse`, `properties`. |
| `rest` | `uri` required. Optional `warehouse`, `auth`, `properties`. |
| `polaris` | `uri` and `warehouse` required, plus `auth` |
| `lakekeeper` | `uri` and `warehouse` required, plus `auth` |

For `generic`, `type` is an iceberg-go catalog type (`sql`, `hive`, `glue`, …)
and `properties` is free-form, passed to iceberg-go. For `polaris`, `uri` is
the REST endpoint (typically ending `/api/catalog`) and `warehouse` is the
catalog name in Polaris. For `lakekeeper`, `uri` ends in `/catalog`.

REST-style providers share an `auth` object:

| Field | Default | Description |
| --- | --- | --- |
| `auth.type` | `none` | `none`, `bearer`, or `client_credentials` |
| `auth.token` | — | Bearer token. Required for `bearer`. Secret. |
| `auth.client_id` / `auth.client_secret` | — | Required for `client_credentials`. `client_secret` is secret. |
| `auth.token_uri` | — | OAuth token endpoint. Empty uses the catalog's default. |
| `auth.scope` | — | Optional OAuth scope (Polaris commonly uses `PRINCIPAL_ROLE:ALL`) |
| `auth.audience` / `auth.resource` | — | Optional OAuth audience and resource indicators |

Data files go to the table's storage via the catalog's FileIO. The `s3`/`s3a`/
`s3n`, `gs`, and `azure` schemes are supported. `TestConnection` loads the
catalog and lists namespaces.

## Supported write modes

The sink advertises `full_replace`, `full_append`, `full_upsert`,
`incremental_upsert`, `incremental_delete`, `cdc_append`, and `cdc_merge`. See
[replication modes](/pages/guides/concepts/replication-modes). Delete support
is real and advertised, so `incremental_delete` pipelines can hard-delete rows
from Iceberg tables.

## Table management

`EnsureSchema` creates the namespace and the table with
`write.format.default=parquet`. For an existing table, evolution is
**add-only**. New fields are appended to the schema, while type changes,
nullability changes, and drops are never applied. A resource whose name
collides with Iceberg's reserved metadata names gets a `_` suffix.

### Type mapping

| Logical type | Iceberg type |
| --- | --- |
| `bool` | `boolean` |
| `int16` / `int32` | `int` |
| `int64` | `long` |
| `float32` / `float64` | `float` / `double` |
| `decimal` | `decimal(p,s)` (default 38,9) |
| `string` / `json` | `string` |
| `bytes` | `binary` |
| `date` / `time` / `timestamp` / `timestamptz` / `uuid` | corresponding primitives |
| `array` | `string` (source-native literal text) |
| unknown | `string` |

Primary key fields become the table's identifier fields.

Array columns land as their source's literal text. A table created by an older
Filament version with a `list` column for the same source column must be
recreated; commits fail on the type mismatch rather than rewriting the column.

## Write mechanics and atomicity

The sink implements `filament.Transactional`: `Stage` opens a scope and `Apply`
retains each resource's owned Arrow batches, spilling them to an LZ4 Arrow IPC
file once the buffer passes `stage_buffer_limit_mb`. `Promote` commits every
resource in the stage as an Iceberg transaction and drops the stage only after
all resources succeed. A retry skips resources that already committed. Used
directly without `Stage`, `Commit` opens and promotes an implicit stage.

Buffering validates operations against the bound mode:

- append rejects updates and deletes
- replace rejects deletes
- upsert, delete, and merge require key fields

At commit, batches are conformed to the table's Arrow schema (including int16
to int32, UUID text to UUID, and unbounded numeric text to decimal(38,9)) and
streamed to the Parquet writer batch by batch. The sink reloads each table from
the catalog first, picking up freshly vended storage credentials, and opens one
Iceberg transaction:

- **append**: `txn.Append` of Arrow record batches in 8,192-row chunks.
- **replace**: `txn.Overwrite` with the run's records. A replace run that
  produced **zero records still overwrites the table to empty**. An empty
  source empties the destination.
- **upsert / delete / merge**: records are collapsed to the latest entry per
  key (later ops win), then applied as `txn.Delete` or `txn.Overwrite` with a
  key filter.

Nothing is visible to readers until each resource's transaction commits, so
per-run visibility is effectively exactly-once. `Commit` is retry-safe.
Resources that already committed are skipped on a retried commit.

## Failure behavior

`Abort` discards the in-memory buffers and temporary spill files. No catalog
or object-store state was written before `Commit`, so a failed run leaves
every destination table exactly as it was.
