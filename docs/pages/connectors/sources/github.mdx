The GitHub source reads repository and organization data, including stars,
watchers, issues, and pull requests. It is built with an
[HTTP manifest](/pages/connectors/building-a-connector/http-manifests) and is
**beta**. Its resources are stable, though future releases may add columns.

## Configuration

| Field | Scope | Default | Description |
|---|---|---|---|
| `token` | Connection | | Required. Secret. Personal access token or GitHub App installation token. |
| `organization` | Connection | | Required. GitHub organization login. |

## Resources

Resources cover repositories, stars, watchers, forks, issues, pull requests,
comments, reactions, releases, code, members, teams, Actions, deployments,
traffic, statistics, Projects, security alerts, and Discussions. Only selected
resources are emitted; their parents are scanned as needed.

Issues and pull requests include open and closed items. GitHub's issues
endpoint also returns pull requests, identified by the `pull_request` marker.
`stargazers` includes `starred_at`; `watchers` lists subscribers.
`repository_details.subscribers_count` is the actual watcher count, while
GitHub's legacy `watchers_count` counts stars.

## Modes

All resources support full reads. If interrupted, a full read of a top-level
resource resumes after its last completed page. Child resources restart.

Three resources support incremental reads:

| Resource | Cursor field | Request parameter | Checkpoint key |
|---|---|---|---|
| `issues` | `updated_at` | `since` (query) | `issues_updated_at` |
| `issue_comments` | `updated_at` | `since` (query) | `issue_comments_updated_at` |
| `pull_request_review_comments` | `updated_at` | `since` (query) | `pull_request_review_comments_updated_at` |

Each uses a `time` comparator, a shared watermark across repositories, and a
300-second overlap. The cursor field is fixed; the lookback window is
configurable. All other resources are full-only.

Use full replace for current membership, such as stars and watchers, to remove
missing rows. `issue_timeline` has no primary key and supports replacement.
Use full upsert for `traffic_views` and `traffic_clones` to retain history
beyond GitHub's 14-day window.

## Behavior

- **Auth**: bearer token from `token`. Grant read permissions for selected
  resources. Star and watcher identities require repository admin or
  collaborator access; restricted listings can be empty. Installation tokens
  are not refreshed automatically.
- **Pagination**: `Link` headers with `per_page=100`; star history uses 30.
  Discussions use GraphQL cursors.
- **API version**: pinned via `X-GitHub-Api-Version: 2022-11-28`.
- **Rate limiting**: one request per second, with manifest-defined throttling
  rules honoring `Retry-After` and budget-reset headers.
- **Statistics**: pending responses are retried; results retain their native
  JSON shape. GitHub's endpoint-specific history and size limits still apply.
- Every resource carries a `raw` remainder column preserving fields the
  manifest does not project.

## Troubleshooting

For a `teams` 403, grant **Organization permissions → Members → Read** on a
fine-grained token, or `read:org` on a classic token, with any required approval
or SSO authorization. Otherwise, deselect both `teams` and `team_members`.
[List teams requirements](https://docs.github.com/en/rest/teams/teams#list-teams).
