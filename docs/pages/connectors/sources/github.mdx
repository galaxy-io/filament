GitHub is a manifest-driven source on the shared [HTTP connector](/pages/connectors/building-a-connector/http-manifests).
The `connectors/http/manifests/github.yaml` manifest declares resources
scoped to a single organization, covering its repositories and the issues
and pull requests in each of them. The connector is **beta**. The resource
set is stable, though field shapes may still be extended.

## Configuration

| Field | Scope | Default | Description |
|---|---|---|---|
| `token` | Connection | | Required. Secret. Personal access token or GitHub App installation token. |
| `organization` | Connection | | Required. GitHub organization login. |

## Resources

`repositories` lists every repository in the organization (all types, sorted
by full name) and captures each repository name. `issues` and `pull_requests`
fan out from it, one paginated walk per repository, with the repository name
denormalized onto every row. Both request `state: all`. `issues` sorts by
`updated` ascending so the incremental watermark advances monotonically, and
each row keeps a `pull_request` marker because GitHub's issues endpoint
returns pull requests as issues.

## Modes

Full is always available. A full run checkpoints its pagination cursor per
top-level resource and resumes from the last completed page.

`issues` is the one incremental resource.

| | |
|---|---|
| Cursor field | `updated_at` |
| Request parameter | `since` (query) |
| Comparator | `time` |
| Checkpoint key | `issues_updated_at` |
| Overlap | 300 seconds |

The cursor field is fixed by the manifest. Only a lookback window is
user-configurable, and only because the comparator is `time`. Issues fan out
across repositories but share a single durable watermark for the whole
resource. The 300-second overlap re-reads a window on each run to cover
repositories that changed while an earlier repository was being scanned.
`pull_requests` has no incremental block and is always read in full.

## Behavior

- **Auth**: bearer token from `token` on every request.
- **Pagination**: RFC 5988 `Link` headers (`rel="next"`), with `per_page=100`
  set as a default query parameter.
- **API version**: pinned via `X-GitHub-Api-Version: 2022-11-28`, so payload
  shapes do not drift with GitHub's rolling default.
- **Rate limiting**: no client-side limiter is configured. The engine backs
  off on 429 responses using `Retry-After`.
- Every resource carries a `raw` remainder column preserving fields the
  manifest does not project.
