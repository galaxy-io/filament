Attio is a manifest-driven source on the shared [HTTP connector](/pages/connectors/building-a-connector/http-manifests).
The `connectors/http/manifests/attio.yaml` manifest declares resources
covering the full CRM surface, from objects and their records to lists and
entries, notes, tasks, meetings, and call transcripts. The connector is
**alpha**, so resource coverage and field shapes may still change between
releases.

## Configuration

| Field | Scope | Default | Description |
|---|---|---|---|
| `api_key` | Connection | | Required. Secret. Attio workspace API key. |

## Resources

| Resource | Parent | Notes |
|---|---|---|
| `objects` | | Object definitions. Captures `api_slug` for children |
| `records` | `objects` | One `POST /records/query` walk per object |
| `object_attributes` | `objects` | Attribute schema per object |
| `object_views` | `objects` | Views per object |
| `record_entries` | `records` | List memberships, one request per record |
| `files` | `records` | Files attached to a record, one request per record |
| `threads` | `records` | Comment threads, one request per record |
| `lists` | | Captures each list's `api_slug` for children |
| `entries` | `lists` | One `POST /entries/query` walk per list |
| `list_attributes` | `lists` | Attribute schema per list |
| `list_views` | `lists` | Views per list |
| `workspace_members` | | Single unpaginated page |
| `notes` | | Workspace-wide notes |
| `tasks` | | Workspace-wide tasks |
| `meetings` | | Captures `meeting_id` for recordings |
| `call_recordings` | `meetings` | One request per meeting |
| `transcripts` | `call_recordings` | One transcript per recording |
| `webhooks` | | Webhook subscriptions |
| `people`, `companies`, `deals`, `users`, `workspaces` | | Query the standard objects directly, without the `objects` fan-out |

The fan-out runs three levels deep. `objects` feeds `records`, which feed
`record_entries`, `files`, and `threads`, while `meetings` feed
`call_recordings`, which feed `transcripts`. Each child issues at least one request per parent
record, so a workspace with 50,000 records costs at least 150,000 requests
when the three per-record children are all selected. Select only the
resources you need.

## Modes

Full only. The manifest declares no `incremental` blocks, so every run re-reads
every selected resource from the start. Full runs checkpoint their pagination
cursor per top-level resource and resume from the last completed page. Child
resources always restart with their parent.

## Behavior

- **Auth**: bearer token from `api_key` on every request.
- **Pagination**: offset paging on the query endpoints (injected into the
  POST body for `records` and `entries`, into the query string for attribute
  and entry lists), cursor paging with null termination on views, files,
  meetings, and call recordings, and single-page responses elsewhere.
- **Rate limiting**: the manifest configures no client-side rate limit. The
  engine still backs off on 429 responses, honoring `Retry-After` for up to 10
  attempts, but a deep fan-out drives requests as fast as Attio will accept
  them. Expect 429 churn on large workspaces.
- Every resource carries a `raw` remainder column preserving fields the
  manifest does not project.
